Проект отслеживает цены на топливо в Украине. Но интересен он не дашбордом, а тем, что у него нет сервера, нет базы данных и нет бэкенда — и при этом он ежедневно публикует посты в Instagram и Telegram сам, без участия человека. Всё живёт внутри GitHub-репозитория.

Главное

Вся система — это один Git-репозиторий и планировщик GitHub Actions

Обычно у такого проекта был бы сервер: cron собирает данные, кладёт в PostgreSQL, бэкенд отдаёт API, отдельный воркер постит в соцсети. Здесь ничего этого нет.

  • Вместо cron — расписания GitHub Actions (13 сценариев).
  • Вместо базы данных — JSON-файлы в папке public/data/, которые сами воркфлоу коммитят обратно в репозиторий.
  • Вместо бэкенда — статический сайт на GitHub Pages: браузер читает те же JSON-файлы напрямую.
  • Вместо очереди задач — триггер workflow_run: один сценарий запускается по факту завершения другого.

Отсюда главный признак системы: репозиторий пишет сам себя. Из 838 коммитов в основной ветке 760 сделал бот — это 91%. Руками сделано 78.

Механика публикации оказалась неочевидной

Instagram не принимает файл загрузкой. Он скачивает картинку сам по ссылке — значит, файл сначала должен где-то лежать в открытом доступе. Отсюда двухшаговая схема: сценарий рисует картинку, коммитит её в репозиторий (она становится доступна по адресу сайта), и только потом зовёт API.

Хештеги подбираются под содержание

Не фиксированный набор: по общему тегу вроде #пальне пост тонет среди тысяч других. Узкий тег (#Житомирщина) даёт меньше конкуренции — там реально попасть в топ. Сценарий набирает до пяти тегов по слотам: два базовых, вид топлива, география или событие, страна. Instagram с конца 2025 года рекомендует не больше пяти — дальше пост выглядит как спам, и охват режется.

Ограничение API

Настоящую геометку поставить нельзя: в Instagram API с логином через Instagram нет поиска локаций. Поэтому область обозначается хештегом — это обход, а не решение.

Токен продлевается сам

Токен Meta живёт 60 дней. Раз в месяц отдельный сценарий продлевает его и перезаписывает секрет в самом GitHub. Тонкость: встроенный GITHUB_TOKEN не умеет менять секреты, поэтому нужен отдельный персональный токен — на нём эта автоматика однажды и споткнулась.

Telegram

Канал как зеркало рынка

В Telegram работают два независимых сценария на чистом Node — обычные HTTP-запросы к api.telegram.org, без библиотек.

  • Карточка цен — раз в сутки, сразу после сбора. Картинка со всеми видами топлива и спарклайном дизеля за 30 дней. Если библиотека рисования не поднялась, пост уйдёт обычным текстом, а не упадёт.
  • Новости — проверка каждые 2 часа, но не больше одной новости за прогон и не больше четырёх в сутки. Без потолка выходило около десяти в день — для нишевого канала это спам.
Главная идея канала

Канал публикует новости в ту сторону, куда идёт тренд цены. Тренд вверх — идут только новости о подорожании. Тренд вниз — только об удешевлении. Боковой тренд — обе стороны. Смысл в том, чтобы лента не спорила сама с собой: цена растёт, а канал рассказывает, как всё дешевеет.

На сайте при этом показываются все новости — фильтр по тренду работает только для канала.

Как определяется «сторона» новости

Никакого ИИ здесь нет — работают регулярные выражения. Один набор ловит признаки подорожания (подорожало, дефицит, акциз, девальвация, остановка НПЗ, эмбарго), другой — признаки удешевления (подешевело, профицит, укрепление гривны, рост поставок). Совпал только первый — новость «красная», только второй — «зелёная», оба или ни одного — «жёлтая».

Отдельные фильтры отсекают то, что публиковать нельзя или не нужно: внутренние российские сюжеты (дефицит в Москве — не наша тема), но с оговоркой, что новости об ударах по Украине остаются. Для Instagram фильтр строже: военный контент туда не идёт вообще — первый аккаунт забанили за сутки.

Reels

Самая сложная часть: видео собирается с нуля каждый раз

Ролик не берётся из заготовок. Сценарий рисует кадры графика, накладывает их на видеофон через ffmpeg, подмешивает музыку и голос диктора.

Сначала решается, есть ли повод

Ролик должен выходить тогда, когда есть о чём говорить. В спокойную неделю цена двигается на копейки, график превращается в прямую линию — такое видео не досматривают, а за недосмотренные Reels алгоритм режет охват следующим. Поэтому отдельный сценарий проверяет: движение цены за неделю, паузу с прошлого ролика и, если неделя тихая, ищет другой сюжет — обзор месяца, квартала или года, где движение точно есть.

Музыка — только CC0, и это юридическое решение

Фильтр жёсткий: только лицензия CC0 и только с Freesound. Остальные варианты отпадают по причинам, которые проверялись отдельно:

ЛицензияПочему не подходит
CC0Подходит. Коммерция разрешена, атрибуция не нужна — единственный полностью автоматизируемый путь.
BY-NDВ видео запрещена вообще: синхронизация с видеорядом считается производным произведением.
BY-SA«Заражает»: всё видео пришлось бы выпускать под той же лицензией.
BY-NCКоммерческое использование запрещено.

Файл лицензии сохраняется рядом с треком — как доказательство на случай спора.

Голос

Текст для диктора собирается детерминированно из цифр ролика — никакой генерации текста, числа просто округляются. Озвучивает его Gemini TTS. Сбой озвучки не критичен: ролик соберётся без голоса и всё равно выйдет.

Ловушка, на которой система однажды сломалась

Мінфін перестроил страницы, и парсер перестал находить таблицу. Когда нашли новые адреса, выяснилось хуже: в одной таблице между названием сети и ценами есть лишняя ячейка с логотипом, а в другой её нет — колонки съезжали, и цена А-95 попадала в графу А-92. Лечение: выравнивать с конца строки, а не с начала — последние пять ячеек всегда одни и те же виды топлива.

Сбор устроен так, что падение одного источника не рушит остальные: каждый источник обёрнут отдельно и получает три попытки с нарастающей паузой. Если новости не пришли — цены всё равно обновятся. Фатальный случай ровно один: не ответил ни один источник цен, тогда история за день не пишется вовсе, чтобы не занести в неё пустоту.

Данные в файле могут быть разной свежести — и это сделано нарочно

После перестройки Мінфіна разбивка по областям стала приходить не всегда. Простое решение — «нет данных, значит пусто» — обрушило бы больше двух сотен страниц сайта. Поэтому если свежая разбивка не пришла, сбор сохраняет предыдущую и рядом кладёт отдельное поле с датой, когда её видели последний раз. Средние цены при этом свежие. Страницы продолжают работать, а расхождение в датах указано честно, а не замаскировано.

В git попадают не только данные

Картинки и видео тоже коммитятся — иначе Instagram не сможет их скачать. Чтобы репозиторий не распух, чистка встроена в сами сценарии: от карусели хранятся два последних комплекта слайдов, от Reels — три последних ролика, остальное удаляется при следующем запуске.

Сайт

Статика, но 313 страниц

Фронтенд — React 19, TypeScript, Vite, Tailwind, графики на ECharts, карта на Leaflet. Оформление — финансовый терминал: тёмный фон, моноширинный шрифт, бирюзовый акцент.

Приложение работает на маршрутах через решётку (/#/region/…), а такие адреса Google не индексирует. Отсюда пререндер: после сборки отдельный скрипт выпекает обычные статические страницы — по одной на каждую область и сеть, плюс перемножение «топливо × область» и «топливо × сеть», раздел «где дешевле» и страницу зарядок. Итого 313 адресов.

Это не копии одной и той же страницы. Внутри — транслитерация названий по украинскому стандарту, склонение всех 23 областей в местный падеж, место области в рейтинге («3 місце з 23») и перелинковка с соседями по этому рейтингу. То есть у каждой страницы свой текст и свой смысл.

Виджет — это публичный контракт

Любой сайт может вставить две строки кода и получить блок со свежими ценами; виджет самодостаточен, без зависимостей, и даёт обратную ссылку. Важное следствие для разработки: файл с текущими ценами читает не только наш фронтенд, но и чужие сайты по прямой ссылке. Значит, его формат нельзя менять свободно — это внешний интерфейс, а не внутренний файл.

Прогноз — это не ИИ

Блоки «Прогноз» и «Чому змінюється ціна» считаются на клиенте: взвешенная линейная регрессия по 90 дням, где свежие точки весят больше, а коридор неопределённости расширяется как корень из числа дней. Уверенность выводится из качества подгонки. Факторы (нефть, курс, моментум, новости) оцениваются по силе и сопровождаются готовым объяснением, как каждый из них работает.

Почему посты привязаны к сбору, а не к часам

GitHub задерживает запуск по расписанию на час-два — это нормальное поведение, а не сбой. Пост по фиксированному времени регулярно выходил раньше, чем приходили данные, и показывал вчерашние цены. Поэтому публикации запускаются не по часам, а по факту завершения сбора: триггер workflow_run.

Решения

Что в этом проекте стоит объяснить отдельно

Состояние в git вместо базы данных

Файл вида {"lastDate":"2026-08-21","postedAt":"..."} коммитится вместе с данными. Это и есть защита от дублей: сбор запускается дважды в день, но пост цен выходит один раз, потому что второй запуск видит в файле ту же дату и молчит.

Данные коммитятся первыми, публикация — потом

Порядок шагов выбран сознательно. Сбой в соцсетях не должен блокировать обновление сайта — сначала данные попадают в репозиторий, и только затем идут попытки публикации.

Проверять фактом, а не ответом API

Instagram может вернуть ошибку и всё равно создать пост. Ответу API нельзя верить — нужно смотреть, что реально произошло в аккаунте. Это правило появилось после двух одинаковых постов в ленте.

Надёжность вынесена в рантайм

Линтер и форматирование настроены, но в конвейере не запускаются; тестов нет, единственная автоматическая проверка — компиляция типов при сборке. Взамен защита стоит на каждом шаге выполнения: повторные попытки, мягкая деградация, продолжение при ошибке публикации, проверка результата фактом. Это осознанный размен, а не забывчивость — но знать о нём стоит.

Почти нет зависимостей

Разбор HTML, RSS, классификация новостей — всё на регулярных выражениях и встроенном fetch. Из тяжёлого только рисование картинок и ffmpeg для видео. Меньше зависимостей — меньше того, что сломается само по себе.

Что не работает

Честный список ограничений

  • Не видно просмотров и охвата. Через API доступны только лайки и число комментариев. Метрики требуют прохождения проверки приложения в Meta, а она ещё не подана. Код для метрик уже написан и молча возвращает пустоту — как только право дадут, цифры появятся сами.
  • Не видно текстов комментариев и директа. Та же причина. Мост «комментарий → Telegram» написан и работает вхолостую.
  • API не меняет профиль. Описание аккаунта и ссылку в шапке можно править только руками.
  • Музыку из библиотеки Instagram взять нельзя — только собственный аудиофайл. Отсюда возня с лицензиями.
  • Видеофоны для Reels генерируются вручную. Автоматизировать веб-студию не получилось, готовые клипы просто лежат в репозитории и чередуются.
